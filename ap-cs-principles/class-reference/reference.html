The course

An introductory college level computing course. You do not need any coding background to do well here.

What this class is about

How the things you use every day actually work

If you have ever wondered how the apps and websites you use are built, this is the course. We look at how computers and technology shape daily life: how the apps you use are put together, how your personal data gets collected, and the good and the damage that technology can cause. You will also build real programs of your own.

Skills you will learn

  • Making connections between concepts in computing
  • Designing a program to solve a problem or complete a task
  • Applying abstractions in computation and modeling
  • Analyzing computational work
  • Communicating ideas about technology and computation
  • Working collaboratively to solve problems

Equivalency and prerequisites

How exam day works

3 hours · fully digital

You take it in Bluebook

Reference materials are provided during the exam. Download Bluebook ahead of time and take the practice test so the app is not new to you in May.

The short version

What you are actually making

You design and write a program that solves a problem, explores something you care about, or is just creative. Then you submit three things through the AP Digital Portfolio: your program code, a video of the program running, and a Personalized Project Reference. On exam day you answer written questions about your own code, and you get to look at your Personalized Project Reference while you do it.

Code + Video + Personalized Project Reference → submitted as final → questions about them on the exam.
Non negotiable

All three components must be submitted as final

Only files marked as final get sent for scoring. If you upload a file but never hit "Submit Final" and attest that the work is yours, it does not count. And if your Personalized Project Reference is not final by the deadline, you will not have it in front of you during the exam, which makes the written questions much harder.

Component A: Program code

One PDF with all of your code, including your comments. You may write this with one or two partners.

Your program must contain

Six required elements

  • Instructions for input from the user, a device, an online data stream, or a file. A user action that triggers an event counts as input.
  • At least one list (or other collection type) that stores data, manages complexity, and helps the program do its job.
  • At least one procedure you wrote yourself, where you defined the name, the return type if needed, and one or more parameters.
  • An algorithm inside that procedure that uses sequencing, selection, and iteration.
  • At least one call to your own procedure.
  • Instructions for output that comes from the input and the program's functionality. Output can be visual, textual, audible, or tactile.
Event handlers and main methods are built in, so they do not count as your own procedure. Your parameter has to actually change what the procedure does.
The list test

Your list has to earn its place

The list should make the program easier to write, or easier to maintain later. If someone could replace your list with two or three normal variables and lose nothing, it is not managing complexity. A one element list never counts. Ask yourself: if this list grew to 200 items tomorrow, would my code still work?

Giving credit

Anything you did not write gets a comment

Starter code, an API, open source code, or code you built with an AI tool all need a comment saying where it came from. If you use existing code, you have to extend it with new functionality of your own.

// This code was provided as starter code by my teacher.
// This code was made freely available by [source].
// This code was generated using [AI tool name].

Component B: Video

One video of your program running. You make this alone. No help from your partner, no help from anyone.

Must show

Three things, in one minute or less

  • Input going into your program
  • At least one piece of the functionality you built
  • Output that your program produces
Format: .webm, .mp4, .wmv, .avi or .mov · Length: 60 seconds maximum · Size: 30 MB maximum

Two things that will sink your video

  • Anything that identifies you. No name on screen, no face, no school.
  • Voice narration. Text captions are fine and encouraged, but nobody talks.

Screenshots and storyboards do not count. The program has to be running.

Component C: Personalized Project Reference

Four screen captures of your own code. This is the only thing you get to look at during the written section of the exam, so make it readable.

Procedure section

Two code segments

  • Your student developed procedure: it defines a name, a return type if needed, has one or more parameters that affect what it does, and implements an algorithm with sequencing, selection and iteration.
  • The place in your program where that procedure gets called.
List section

Two more code segments

  • How data gets stored in your list.
  • That same list being used, for example creating new data from existing data or accessing multiple elements, as part of the program's purpose.

This one gives a zero

Your Personalized Project Reference cannot include comments or course content. Take the comments out of your code before you make the screen captures. Leaving them in scores a 0 on the whole Create performance task, including your written responses on the exam.

Screen captures must not be blurry. Text must be at least 10 point.

Why this matters now

Pick a program you can explain out loud

The exam does not ask you to write new code. It asks you to explain the code you already wrote, months later, without your computer. A flashy program you barely understand scores worse than a simple program you know line by line.

The rules

Once the task is officially assigned, these apply. They come straight from the College Board task directions.

Allowed

You may

  • Work with one or two partners on the ideas, the code, the debugging and the testing.
  • Use a generative AI tool as support while you learn, develop and debug, as long as you credit it and you understand every line.
  • Ask me to clarify the directions and the submission requirements.
  • Ask me for help with a broken computer, a network problem, or saving and exporting files.
  • Work on the task outside of class time.
  • Keep a programming journal of your design decisions. This is a very good idea.
Not allowed

You may not

  • Get help writing, fixing, debugging or revising your program from anyone except your partners.
  • Collaborate on the video or on the Personalized Project Reference. Those two are individual, always.
  • Submit a practice task, a sample from AP Central, or a project from a curriculum provider.
  • Change anything after you submit as final.

Plagiarism

Using code, media, data or evidence made by someone else or by an AI tool without crediting it is plagiarism, and it scores a 0 on the Create performance task including the written responses on the exam. Crediting it takes one comment line. Do it.

Read this before you copy the format

The written responses look different now

In 2023 students uploaded their written responses together with the program. Today you answer those questions on the exam instead, using your Personalized Project Reference. The videos and the programs are still exactly the kind of thing you should be making, and the graders' comments still tell you what earns points. You cannot submit any of this work as your own.

Ideas that work

Look at the samples above and you will notice a pattern: something takes input, a list holds the data, a procedure decides what happens. Start from something you actually care about.

  • A recommender. Songs, movies, books, food in Tampico, a workout. Questions in, list of options filtered, one suggestion out.
  • A quiz or study app. Flashcards for another class, a vocabulary trainer, a practice test with a score history.
  • A tracker. Spending, habits, hours of sleep, homework. Store entries in a list, then calculate an average or a total.
  • A game with a scoreboard. Any simple game, as long as a list stores the scores or the game state and a procedure sets the difficulty.
  • A calculator for something real. Splitting a bill, the grade you need on the final, converting units, a training pace.
  • A small simulation. Physics, population growth, a dice or card experiment run hundreds of times.
  • A tool for our school. A club sign up, a schedule lookup, a random group generator, a lost and found log.
Good sign: you can say the purpose in one sentence that starts with "so that". Bad sign: the only way to describe it is to list what happens on screen.
Our plan

The College Board gives you at least 9 hours of class time for the Create task. Here is how we will use it. Dates get confirmed in class.

StageWhat you finish
Stage 1Pick your idea and write the purpose in one sentence. Sketch the interface on paper.
Stage 2Plan your list and your procedure before you code. What does the list hold, and what does the procedure decide?
Stage 3Build the core functionality. Test it with different inputs as you go.
Stage 4Finish, clean up and comment your code. Export the program code PDF.
Stage 5Record the video. Under 60 seconds, under 30 MB, captions instead of narration.
Stage 6Remove comments from your four code segments and build the Personalized Project Reference.
Stage 7Upload all three components and submit each one as final in the AP Digital Portfolio.
Stage 8Practice the four written response prompts using your own reference.
